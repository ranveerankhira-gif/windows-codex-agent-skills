# 分类与目录规范

## 固定目录

```text
项目名/
├─ 01_给Codex审核/
│  ├─ 当前正式版/
│  │  ├─ 01_项目说明/  02_文案与分镜/  03_图片与封面/
│  │  ├─ 04_配音字幕音乐/  05_预览片/  06_最终成片/
│  │  └─ 07_问题与修改记录/
│  └─ 历史版本/
├─ 02_工程源文件/
│  ├─ 01_原始视频/  02_原始图片/  03_原始音频/
│  ├─ 04_剪辑与时间线工程/  05_字幕与排版/
│  ├─ 06_生成过程文件/  07_渲染中间产物/
│  ├─ 08_平台发布包/  09_备份与历史版本/
│  └─ 10_项目附属资料/
└─ 03_机器清单_勿手改/
   ├─ 01_项目清单/  02_文件索引/  03_依赖关系/
   ├─ 04_来源与交接/  05_质检报告/
   ├─ 06_日志与维护历史/  历史快照/
```

## 强制判断顺序

1. 读取工程清单、项目文件、引用关系、来源记录和交接文件。
2. 用文件头识别图片、音频、视频、PDF、ZIP/Office、JSON、文本、数据库、可执行文件和通用二进制，不盲信扩展名。
3. 结合相对路径、文件名、版本词、平台名和相邻文件判断生产用途。
4. 主分类表示主要生产用途；附加用途写入标签。
5. 每个文件都必须落到具体类别。禁止建立任何名称含“待分类、未知、不明、其他、unknown、unclassified”的目录、子类或状态。

## 具体分类

- 备份、归档、历史版本和损坏文件 → `09_备份与历史版本`。
- 项目清单、索引哈希、依赖绑定、来源交接、质检报告、运行日志 → `03_机器清单_勿手改` 对应子目录。
- 视频 → 原始视频、渲染中间产物或平台发布包；没有交付或渲染证据时归原始视频。
- 图片 → 原始图片、生成过程图片、渲染阶段图或发布封面。
- 配音、环境声、音乐 → 原始音频，并用标签细分。
- 字幕、字体和排版布局 → 字幕与排版。
- 剪辑工程、时间线、项目数据库和工程配置 → 剪辑与时间线工程。
- 文案、分镜、说明、反馈、许可证 → 项目附属资料下的对应具体子类。
- `.py/.ps1/.js/.bat/.cmd/.sh` → `自动化工具`。
- ZIP/7z/RAR/TAR 等压缩内容 → `压缩归档文件`。
- SQLite、缓存、模型权重或通用数据容器 → `工程数据或缓存`。
- DLL、插件、未知扩展但确认为二进制的数据 → `工程辅助二进制文件`。

## 副本规则

- 审核副本默认不超过 50 MiB；更大的文件只登记源路径和哈希。
- 通过校验的当前 `final-delivery` binding 和其依赖不受 50 MiB 上限影响；正式母版或平台包不得被静默跳过。
- 一个项目可以有一个完整工程源和多个精炼审核源。工程索引只统计完整工程一次；审核源另记，不得重复计入源文件数。存在有效正式交付清单时，由它决定当前审核视图，普通审核源不得混入当前正式版。
- 审核副本保留源内相对层级；同名文件位于各自镜头、画幅、阶段或平台路径中，不使用拍扁目录加哈希后缀的方式维持碰撞。
- 正式母版由 `final-delivery` binding 角色判定为 `06_最终成片`，不依赖文件名是否含 `final`。平台视频、平台封面、包清单、计划、provenance 与 QA 必须跟随当前正式版进入相应审核分类。
- 刷新当前机器清单前，把旧清单完整复制到时间戳快照。
- 审核副本不是工程权威源；机器索引始终指向登记的原工程。
