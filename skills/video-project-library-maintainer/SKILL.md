# 视频工程资料管家

审计或登记项目前读取 [安全与权限](references/security-and-permissions.md)。

把视频项目整理成用户容易审核的视图和机器容易维护的清单，同时保护原工程路径、素材引用和历史证据。

## 硬边界

- 公共资料库由 `--library-root` 或 `VIDEO_PROJECT_LIBRARY_ROOT` 明确指定；桌面只放快捷入口，不把大型工程误复制到系统盘。
- 旧工程默认登记，不移动、不删除、不重命名、不覆盖源文件；新工程才可直接创建在资料库中。
- 写操作必须先运行无 `--apply` 的预演。核对预演后，才用完全相同的参数加 `--apply`。
- 所有路径参数必须是绝对路径；路径任一现有组件包含符号链接或 Windows 重解析点时拒绝执行。项目名拒绝 Windows 保留设备名。
- 只维护带 `.video-project-library-managed-project.json` 所有权标记且标记内容与当前目录一致的既有项目；同名非受管目录不得接管。
- 写入使用项目独占锁和带所有权标记的事务暂存目录。审核视图、源位置记录和机器清单作为一组提升；任一步失败都恢复旧状态。
- 每个源文件必须获得一个且仅一个主分类。空分类、漏项、重复记录，以及任何“待分类、未知、不明、其他、unknown、unclassified”类别均使门控失败。
- 分类必须基于文件头、格式、工程引用、原目录、文件名和相邻文件关系。陌生文件也按可验证属性归入具体类别，例如工程配置、自动化工具、压缩归档、缓存数据、许可证说明或工程辅助二进制文件。
- 文件无法读取时归入 `备份与历史版本/损坏或不可读文件`，保留原位并记录错误。
- 拒绝路径越界、符号链接和 Windows 重解析点。不得通过链接扫描项目外部。
- 不联网、不上传、不下载、不发布，不修改剪辑软件或系统全局配置。

## 使用流程

1. 先读 [分类与目录规范](references/classification-rules.md)。
2. 使用 `scripts/maintain_video_library.py`：`init-library` 初始化资料库和桌面快捷方式；`new-project` 创建空工程；`register` 登记旧工程；`refresh` 刷新清单；`verify` 只读核验。旧工程已有精炼交付目录时，用一个或多个 `--review-source` 指定审核源；机器索引仍覆盖完整 `--source`，审核区只复制精炼源。
   - 若源工程存在一个或多个 `delivery/final-delivery*.json`，最新的 `status: passed` 清单是“当前正式版”的唯一入口。先验证清单自身、全部 binding 路径、大小和 SHA-256，再递归收集其 JSON 依赖；任何缺失、越界或哈希失效都阻止写入，不能退回旧版冒充当前版。
   - 每个 binding 必须同时提供安全相对路径、64 位 SHA-256 和非负整数 `size`。依赖 JSON 受文件大小、嵌套深度和依赖数量上限约束；疑似文件路径无法解析时阻止写入。
   - 只有没有正式交付清单的工程才使用 `--review-source` 形成审核视图；审核源与完整工程的文件计数必须分开，不能因审核源位于工程内部而重复膨胀索引。
3. 先检查预演 JSON 的 `classification_gate.passed`、文件总数、分类统计、低置信度记录和写入动作。门控未通过时禁止 `--apply`。
4. 写入后再次运行 `verify`，分别报告原工程是否改变、审核视图是否生成、机器清单是否通过、是否存在不可读文件。

## 两套视图

- `01_给Codex审核` 分成 `当前正式版` 与 `历史版本`。当前版保存适合 Codex 与用户共同检查的说明、文案分镜、图片封面、配音字幕音乐、预览片、正式母版、四平台包和修改记录；必须保留源工程内的相对层级，禁止把不同镜头、画幅或阶段文件拍扁到同一目录。历史区至少保留旧交付清单，旧审核视图随维护快照归档。
- `02_工程源文件` 保存新工程本体，或为旧工程保存明确的原位置记录。大型旧素材不复制。
- `03_机器清单_勿手改` 保存项目清单、文件索引、SHA-256、依赖线索、来源交接、质检、日志和维护历史。

刷新机器清单前必须归档旧版本。审核视图、源位置记录和机器清单先在暂存目录完整生成并核验，再作为单次事务提升；提升失败必须恢复三者的旧状态。源工程文件绝不覆盖。并发维护请求由独占锁拒绝，源工程在预演后发生变化时要求重新预演。

## 完成标准

只有工程源文件数与工程索引数一致、每个文件只有一个具体主分类、所有哈希已记录或有明确读取错误、无越界路径、当前 `final-delivery` 全部 binding 有效、当前正式版审核副本零缺项零过时文件、正式母版和四平台包分类正确、审核副本可追溯、重复刷新不堆积当前视图且 `verify` 通过，才可说“整理完成”。`verify` 不得只拿旧索引与当前扫描互相对账。自动检查通过不等于用户已经审核内容。
