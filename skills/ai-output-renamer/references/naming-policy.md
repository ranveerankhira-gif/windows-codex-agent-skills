# 命名与计划协议

## 中文语义命名

- 格式：`核心内容_具体用途[_版本][_日期].扩展名`。
- 保留能区分内容的版本号和日期，删除重复的“修正版、交付版”等尾词。
- 中文优先；产品名、标准缩写和代码标识确有价值时可以保留。
- 不改变扩展名，不把 `new-chat`、时间戳或哈希直接当标题。
- 同组附件共享名称主体，并以 `_转写稿`、`_分段数据`、`_元数据` 等结尾。
- 文件名应简洁，通常不超过 80 个中文字符；不得包含控制字符、Windows 非法字符、路径分隔符、末尾点／空格、`.`／`..` 或 `CON`、`NUL`、`COM1` 等保留名称。
- `SKILL.md`、`openai.yaml`、`output.pdf` 等通用名不能原样进入资料库。应从文件内容、配置中的显示名或所属项目中提取名称，例如 `Codex任务改名器_Skill说明.md`。

## 内容核验

- 文件名、源目录和扩展名只用于定位，不能单独作为主题结论。
- 文件较少时逐个读取；大量版本文件至少覆盖所有内容家族，并读取最新版本或能代表差异的版本。
- OOXML 文档没有正文文本时，检查 `word/media`、`ppt/media`、图表和嵌入对象。截图型文档不能因为文本提取为空就当作空文件。
- OCR 或渲染工具不可用时，直接查看内嵌图片。证据有限时结合内容、标题、来源和关联文件作最佳判断，不等待人工分类。
- 主题名必须能被目录内真实内容支持。不要把“看起来像课程材料”写成“作业”，也不要用单一关键词覆盖复合内容。

## 文件夹策略

优先保持现有目录深度与父子结构，但必须独立评估文件夹名称。保留层级不等于保留旧名称：主题名应概括目录内的真实内容，而不是沿用过宽、含糊或仅用于临时归档的旧标题。即使分类位置没有错误，也可以优化显示名称。

当内容已经形成清晰子主题时，允许拆分、合并或调整层级；只有这种结构变化能明显改善查找时才执行。任何文件夹改名或结构调整都必须通过稳定键、索引和刷新器映射完成，禁止只改磁盘目录。

默认稳定主题键如下，显示名称可随内容演变：

- `research`：研究资料
- `study`：学习与课程
- `work`：工作项目
- `design`：设计与创作
- `tools`：AI工具与系统维护资料
- `personal`：个人与生活
- `other`：其他主题

不使用 `unclassified` 或“待分类”。确实横跨多个主题，或不适合现有主题的文件使用 `other`；这表示系统已经作出“其他主题”的判断，不是等待用户处理的临时状态。

类型键使用 `documents`、`spreadsheets`、`presentations`、`images`、`media`、`code_data`、`archives`、`other`。

## 来源与并发

- `Hash` 是副本的稳定身份；文件名、来源路径、AI 名称和账号名都不是身份键。
- `SourceApps` 保存所有来源 AI，`SourceInstances` 保存明确的“AI / 账号或实例”，`SourcePaths` 保存所有发现路径。重命名和移动集中副本时必须原样保留这些数组。
- 同一哈希来自多个来源时只合并索引；同名不同哈希必须生成不同目标路径，禁止覆盖。
- 浏览器来源标记通常只能识别 AI 平台，不能识别同一平台中的账号。不得伪造账号归属。
- 刷新器和重命名器必须沿用同一个互斥锁；事务标记存在时刷新器停止，不并发修改索引。

## 计划 JSON

```json
{
  "schemaVersion": 1,
  "namingRevision": 1,
  "folderNames": [],
  "items": [
    {
      "hash": "完整 SHA-256",
      "newFileName": "中文语义名.ext",
      "newTopicKey": "tools",
      "newKindKey": "code_data",
      "quarantine": false,
      "reason": "简短命名依据"
    }
  ]
}
```

`folderNames` 用于独立修改文件夹显示名。文件夹名发生变化时，应把该稳定键下的现有记录加入计划，保持其文件展示名不变，只让应用脚本迁移路径并更新索引：

```json
{"scope":"topic","key":"tools","newName":"AI工具与系统维护资料"}
```

临时锁文件设置 `quarantine: true`，此时其他目标字段可以沿用现值。
