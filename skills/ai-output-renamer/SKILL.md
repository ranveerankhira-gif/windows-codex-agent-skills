# AI 输出中心智能命名

执行前读取 [安全与权限](references/security-and-permissions.md)。

仅处理通过 `-LibraryRoot` 或 `AI_OUTPUT_LIBRARY_ROOT` 明确指定的集中副本库。目录必须已经包含 `_系统与索引/文件索引.json`；卷根目录、符号链接、Windows 联接点和其他重解析点会被拒绝。任何情况下都不得改名、移动、删除或写入索引中 `SourcePaths` 指向的源文件。首次使用前复制 `config.example.json` 到库外的私有位置并按实际目录配置；真实配置不得提交。

## 整理新文件

1. 运行 `scripts/Get-AIOutputRenameInventory.ps1`，读取尚未应用当前命名版本的记录。该步骤只在副本库之外创建新的清单文件，不创建或改写库内配置，也不覆盖已有清单。
2. 阅读 [references/naming-policy.md](references/naming-policy.md)，并读取副本的实际内容后再判断文件名和主题。小批量应逐个读取；大量版本文件应覆盖每一种内容家族并检查最新或代表版本。禁止只凭原文件名、父目录名或扩展名作语义分类。
3. 如果 Word、PowerPoint 等文件几乎没有可提取文本，继续检查压缩包内部的媒体、截图、图表和嵌入对象。OCR 不可用时直接查看内嵌图片。证据有限时仍须根据全部可用信息作出最佳分类，不要求用户确认；确实跨主题或不属于现有主题的文件归入 `其他主题`。
4. 为清单生成 JSON 计划；格式遵循参考文件。全部自动命名，无需逐项询问。`SKILL.md`、`openai.yaml` 等通用文件名必须从内容或所属项目中提取真实名称作为前缀。
5. 运行 `scripts/Apply-AIOutputRenamePlan.ps1 -PlanPath <计划文件>`。
6. 检查脚本摘要，并用刷新脚本连续刷新两次。再次运行清单脚本；如果刷新期间收录了新文件，继续执行“读取内容 → 命名 → 刷新”循环，最多三轮。结束条件是待命名记录为 0，且两次刷新均未重建旧名或旧文件夹；三轮后仍有新增则停止并报告清单，不得假装完成。

默认只处理 `NamingRevision` 低于当前策略版本的记录。只有用户明确要求重新评估所有名称时，才给清单脚本传递 `-All`。

文件夹命名与文件命名分开判断。即使没有待命名的新文件，只要当前主题名过宽、含糊或没有反映目录中的实际内容，也应通过稳定键更新文件夹映射。为了让已有副本迁入新显示目录，可用 `-All` 构造只改变路径映射、不改变现有文件展示名的计划。必要时允许拆分、合并或调整层级，但必须同步刷新分类逻辑与稳定键，不能直接在资源管理器中孤立改目录名。

命名一级主题前必须核验该主题内的真实内容。文件名只是线索，不是证据；“经济学作业”等看似合理但未经内容核验的名称不得采用。“尽量保留层级”只约束结构层级，不约束文件夹显示名。

资料库不使用“待分类”目录。不要把判断工作留给用户；完成内容核验后自行选择最合适的现有主题，必要时使用 `other`（显示为“其他主题”）。用户后续反馈错误时再修正索引与名称。

## 来源与多账号

- 保留索引中的 `SourceApps`、`SourceInstances` 和 `SourcePaths`；智能命名只改变集中副本的展示名和分类，不得丢失或改写来源记录。
- 同一文件可能来自多家 AI、多个账号或多个路径。以 SHA-256 作为唯一身份，合并来源数组，不重复创建副本。
- 同一平台的不同账号或实例是不同来源实例，但内容哈希相同仍只保留一个集中副本。
- 不根据浏览器文件名、窗口标题或猜测区分账号。只有 `AI投放区\<AI名称>\<账号或实例>` 这样的明确目录才能记录具体实例。
- 新出现的 AI 不要求修改 Skill：读取刷新器已经保存的来源字段即可。命名和分类不得假设来源只可能是 Codex 或 ChatGPT。

## 撤销

用户明确要求撤销时，运行 `scripts/Undo-LastAIOutputRename.ps1`。它只撤销最近一次未撤销事务，不触碰源文件。

## 强制边界

- 只能把目标设置在本次明确指定且经过规范化的副本库根目录内；扩展名必须保持不变。
- 资料库内部不得创建 `.lnk` 快捷方式；只有 `00_最近新增` 同时带有旧版所有权标记时，脚本才清理其中的遗留快捷方式。无标记目录保持不动。桌面上的资料库入口不在处理范围内。
- 使用 SHA-256 作为稳定身份，不以文件名或路径识别文件。
- 相关文件应共享名称主体，例如转写稿、分段数据和元数据。
- `~$`、下载残片和临时锁文件进入系统隔离区，不做语义命名。
- 如果应用脚本报告哈希不一致、索引损坏或路径越界，停止，不要绕过验证。
- 自动回滚不完整时保留 `.rename-in-progress.json`，阻止刷新器继续运行；必须先人工核对事务、暂存和备份状态。
- Skill 仅显式调用；不要把它变成每次输出文件时自动运行的通用流程。
